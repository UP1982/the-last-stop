# E1 scene editor

From the project root, build the authoritative content tool and native preview:

```sh
odin build tools/content -out:build/tls-content
odin build src -define:DEV_TOOLS=true -out:build/the-last-stop-dev
python3 -B editor/server.py --project-root "$PWD"
```

Open the printed tokenized `http://127.0.0.1:<allocated-port>/#token=...` URL.
Python 3.9 stdlib and plain browser JavaScript/CSS/HTML are sufficient. There is
no Node/npm step. Ctrl+C or SIGTERM shuts down the bridge and its owned preview.

Select an object or safe spawn in the tree or canvas. Drag to move; arrow keys
nudge a canvas selection by the snap interval (one pixel with Snap off).
Shift+drag pans horizontally. Camera X, Frame selection, display scale, grid
and layer visibility affect only the authoring view. Object bounds are local
to its top-left position. Safe spawn coordinates follow their authored kind.
Select the scene root to inspect bounds and named puzzle links.

Place and Duplicate require an explicit fresh stable ID. Delete is undoable.
Deleting a required linked object is allowed in a draft, but authoritative Save
rejects broken references until they are repaired. Undo/redo remains available
after Save; undoing a saved change becomes a new unsaved draft.

Save submits one `restore_document` operation for `oliver_obstacle` with the
original graph `expected_revision`. The CLI validates and commits atomically.
Validation errors retain the draft and undo history. Stale/busy exit 3 opens a
conflict dialog with Keep, Download draft, and explicit Discard & reload actions.
Polling checks the full graph revision every two seconds. External changes never
silently update the draft baseline. Preview uses the last saved content; unsaved
changes are clearly reported as excluded. The actual DEV_TOOLS game, rather than
the labeled authoring approximation, is the gameplay authority.

Draft/history recovery uses browser local storage for the current origin and
canonical project identity. It survives page reloads at the same launch URL.
Random ports mean recovery across bridge restarts is not guaranteed. Use Download
draft before ending a session when a portable recovery copy is needed; import,
automatic merge and durable cross-launch draft storage are deferred to E4.

The bridge binds only 127.0.0.1, pins the canonical project root, checks Host and
Origin, requires a per-launch API token, supplies no CORS headers, restricts static
files, rejects traversal/symlink escape, and accepts only fixed command IDs with
fixed argv construction. It offers no arbitrary file/source/shell endpoint. All
authored-content access goes through `build/tls-content`. The preview session ID
is generated by the bridge; clients cannot supply a save path or command line.

Tests (build `tls-content` first for the real CLI test):

```sh
python3 -B -m unittest discover -s tests/editor_ui -v
```

The pure `web/logic.js` is tested directly through macOS JavaScriptCore with ctypes,
without Node. That test skips explicitly on systems without JavaScriptCore. The
real CLI test copies data/assets and the executable into a fresh temporary root.
It never changes project authored content. `tests/editor_ui/game_window.swift`
locates a single visible game window by its owned preview PID for window-only
`screencapture -l` evidence; it does not capture the desktop.

See `HANDOFF.md` for actual E1 verification, limitations and integration notes.
